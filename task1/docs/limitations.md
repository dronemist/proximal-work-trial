# Limitations & Future Work

## Current Limitations

### No Perceptual Similarity Metric (DreamSim)
The current pixel metric is SSIM, which is mathematically convenient but not perceptually calibrated — it penalizes imperceptible differences (anti-aliasing, sub-pixel shifts) while underweighting visually salient ones (wrong gradient direction, flipped layout). DreamSim (a learned perceptual metric) would better align with human judgment. It requires GPU inference, which is why it's deferred to a pilot wave with Modal GPU containers.

### VLM Judge Calibration
The VLM judge (Claude Sonnet 4.6) acts as a min() ceiling on the structured score. Its calibration is approximate — we've tuned the prompt through iteration, but it still occasionally rates a clearly-different page at 0.7+ or a nearly-identical page at 0.4. Running VLM scores alongside structured metrics (and logging both) lets us measure this drift over time without the VLM dominating the reward signal.


### Anticheat-Reward Coupling
The anticheat multiplier creates a bimodal reward distribution — trials either score near zero (any violation triggered) or in the normal band, with an empty dead-zone between them. For RL training, a subtractive penalty mode preserves gradient signal. The multiplicative penalty is kept for held-out evaluation where "you cheated → near-zero" is the right semantic.

### Single Generator Model
All sites are generated by a single model (Opus 4.7). This means the style distribution reflects that model's biases — particular layout patterns, color choices, and component styles recur. A production system would benefit from mixed generators (different models, temperature settings, or even hand-designed templates) to increase true visual diversity.

### No Functionality Testing
The task explicitly focuses on design replication — no JavaScript, no interactivity, no form submission. This is a deliberate scope constraint, but it means the generated sites lack interactive elements (dropdowns, modals, accordions) that real websites have. The agent is never tested on whether a sidebar collapses on click, only whether it looks collapsed in the mobile screenshot.

## Future Work

### Part 2: Animations
The reference sites are currently static (no `@keyframes`, no `animation:`). Adding animations would require:
- Video recording of references (not just screenshots)
- A temporal comparison metric (frame-by-frame SSIM or optical flow similarity)
- Passing video to the VLM judge alongside screenshots
- Careful anti-cheat for animated SVGs and CSS transitions

### Part 3: Multiple Frameworks
Currently HTML+CSS only. Supporting React+CSS, React+Tailwind, and SolidJS+Tailwind would require:
- Framework-specific scaffolding (package.json, build tooling)
- Build step in the agent environment (npm install, vite build)
- Adjusted grading that accounts for framework-specific rendering differences
- Per-framework benchmarking to understand which frameworks agents handle best

### Improved Layout Metrics
Block_match bbox-IoU is compressed at both ends (see [Results — per-feature variance](results.md#per-feature-variance-is-uneven)): a noise floor from Hungarian assignment forcing spurious pairings between wrapper `<div>`s, and a ceiling from `sqrt(mean_IoU)` compression plus DOMs that are never byte-identical even on visually-perfect pages. Useful as a sanity check, not as a ranking axis. Two promising replacements: (1) grid-cell occupancy — discretize the viewport into cells and compare occupancy patterns, which is translation-tolerant and naturally handles different element granularities. (2) Pixel-space segmentation — detect visual blocks from the rendered screenshot rather than the DOM, making the metric framework-agnostic for Part 3 (React, Tailwind, SolidJS).

### Numeric Fidelity Sub-Metric
The agent consistently invents plausible-looking numbers rather than reproducing exact values from reference screenshots (e.g., "$2,847" → "$2,500"). The text metric partially catches this, but a dedicated digit-level comparison on extracted numeric regions would provide a sharper signal for financial dashboards, KPI cards, and data tables.

### Proxy-Based Network Blocking
The egress proxy currently logs all outgoing connections but doesn't block them. Converting it to a blocking proxy — refusing non-allowlisted hosts at the `CONNECT` handler — would prevent agents from fetching external resources during execution (CDN hotlinking, downloading images, npm registry pulls). This is a one-line change in `proxy.py` but requires careful allowlist maintenance to avoid breaking legitimate Claude Code API calls.

### Expanded Diversity Axes
The current spec system covers 15 domains, 15 archetypes, 12 palettes, and 3 themes. Expanding these pools — more domains (e.g., legal, logistics, education), more archetypes (e.g., timeline, split-screen, mega-menu), more palettes from real design systems (Material, Carbon, Polaris) — would increase the combinatorial space and reduce the chance of stylistic repetition across large batches.

### LLM Judge on Generated References
Currently, reference quality is validated by structural checks (DOM depth, overflow, off-origin requests). Adding an LLM judge pass on the generated websites — evaluating visual coherence, brand fidelity to the spec, and design quality — would catch subtle issues that structural checks miss: awkward layouts that technically pass validation, inconsistent visual hierarchy, or pages that don't match the brand spec's intent. This would act as a quality gate before packaging, filtering out generated sites that are technically valid but visually weak.
